Проверить лабораторную `$ARGUMENTS` (например, `lb1_2` или `lb2`). Если
аргумент не задан - взять лабораторную, которую меняли в этой сессии, или
спросить.

Бинарники и промежуточные файлы класть только в scratchpad-каталог сессии
(на macOS допустим `/tmp`). Не писать в каталоги лабораторных, не трогать
отслеживаемые бинарники. В конце `git status --short` не должен показывать
новых изменений от сборки.

## lb1_x

1. Прочитать `lb1_x/main.cpp`: что программа читает из stdin, вызывает ли
   `system("pause")`, работает ли с файлами (относительные пути - от
   текущего каталога).
2. Собрать.
   - **Windows:** создать в scratchpad `.cmd`-файл и запустить его через
     `cmd //c "<windows-путь>"` из Bash:
     ```bat
     @echo off
     call "E:\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1
     cd /d "%~dp0"
     cl /nologo /std:c++17 /utf-8 /EHsc /W4 /permissive- /fsanitize=address /Zi "<repo>\lb1_x\main.cpp" /Fe:lb1_x.exe /Fo:lb1_x.obj /Fd:lb1_x.pdb
     ```
   - **macOS:**
     `c++ -std=c++17 -Wall -Wextra -Wpedantic -fsanitize=address,undefined lb1_x/main.cpp -o /tmp/oolandsp_lb1_x_san`
3. Запустить на нескольких тестах: обычный случай, граничные значения и
   случай, отличающий правильный алгоритм варианта от ошибочного. Ввод
   подавать через stdin и добавлять лишнюю строку для `system("pause")`.
   На Windows запускать `.exe` тоже из `.cmd` после `vcvars64.bat` (нужна
   DLL ASan). Ограничивать время (`timeout 20`). Для файловых работ
   (lb1_5) запускать из копии каталога в scratchpad, чтобы не перезаписать
   `matrix*.txt` в репозитории.
4. Проверить вывод вручную: видны ли конструкторы/деструкторы, верен ли
   результат для конкретных данных.

## lb2

```bash
"E:/Microsoft Visual Studio/18/Community/MSBuild/Current/Bin/MSBuild.exe" lb2/lb2.slnx -nologo -v:m \
  "-p:OutDir=<scratch-win>\lb2out\" "-p:IntermediateOutputPath=<scratch-win>\lb2obj\"
```

Только Windows. Форму не запускать и не утверждать, что она проверена
визуально.

## Отчет

Раздельно указать:
- что установлено чтением кода;
- что подтверждено компиляцией (с предупреждениями, если были);
- что подтверждено запуском (какие входные данные, какой вывод, есть ли
  ошибки ASan/UBSan);
- что не проверено (например, UBSan на Windows, визуальная часть lb2).
