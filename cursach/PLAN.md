# Курсовой проект по ООЯиСП · вариант 6

**Тема по списку вариантов:** Разработка GUI-приложения «Сколько в массиве элементов, которые представимы в виде произведения двух простых чисел».

**Текущий этап:** Этапы 1–7 выполнены. Следующий шаг — этап 8, сборка и ручные испытания в Windows по [протоколу](TESTS.md).

**Сообщение для нового чата** (замени N номером этапа):

> Прочитай AGENTS.md и cursach/PLAN.md. Выполни только этап N. Перед изменением кода покажи, что уже реализовано, что требуется изменить, и дождись моего подтверждения. После работы запиши в журнал этапа изменённые файлы, фактические проверки и следующий шаг. Проверки интерфейса, которые требуют запуска в Windows, оставь в статусе «ожидает запуска».

## Основа проекта

- Бланк задания, список тем и шаблон записки лежат рядом с этим планом. Условия отдельных задач приведены в разделах 2.2–2.7 пособия Горюнова и Леоновой в корне проекта.
- По выбору пользователя приложение разрабатывается на C# Windows Forms под .NET Framework 4.7.2. В бланке указан C++. Согласование C# с преподавателем пока не подтверждено.
- Работать в копии [app](app/), решение [lb2.slnx](app/lb2.slnx). Исходная лабораторная содержит обработчики других вариантов. Каждый раздел сверять с заданием ниже.
- Принятое соглашение: индексы строк, столбцов и элементов вектора начинаются с нуля. 0 и 1 не являются ни простыми, ни составными.

## Этапы и критерии готовности

### 1. Рабочая копия и план

Скопировать решение, проект, код, ресурсы и исходные данные из lb2 в cursach/app. Сохранить требования, контрольные примеры и порядок передачи между чатами. Проверить совпадение исходных файлов и относительный путь решения к проекту.

### 2. Главное меню и форма

Проверить пункты меню и привязку обработчиков в Form1. Добавить понятные русские названия с номерами ЛБ. Сделать пять разделов: строка (2.2), вектор (2.3), матрица и файлы (2.4–2.5), график (2.6), блуждание (2.7). При выборе показывать только соответствующую группу элементов.

**Проверка:** открыть все пять разделов по очереди и вернуться к первому. Проверить заголовки и видимость элементов на каждом переходе.

### 3. Матрица и подсчёт элементов

Принять размеры от пользователя. По кнопке «Инициализировать» создать матрицу небольших случайных целых чисел, показать в таблице с индексами и записать в текстовый файл. Первая строка содержит два размера, далее одна строка на каждую строку матрицы. После успешной инициализации включить кнопку «Решить». При её нажатии читать числа из файла и считать ячейки, значение которых равно произведению двух простых чисел. Множители могут совпадать. Каждое вхождение учитывается отдельно.

**Проверка:** для матрицы из строк [4, 6, 9, 10, 6] и [−6, 0, 1, 7, 8] ответ 5. Учитываются 4 = 2×2, оба вхождения 6 = 2×3, 9 = 3×3 и 10 = 2×5. Для одной второй строки ответ 0. Проверить недопустимый размер и состояние кнопки до инициализации.

### 4. Открытие и сохранение матрицы

Добавить команды «Открыть» и «Сохранить как» через штатные диалоги Windows Forms и методы файлового обмена этапа 3. После успешного открытия обновить таблицу, размеры и путь для расчёта. При отмене и при ошибке чтения сохранить предыдущие данные и рабочий путь.

**Проверка:** сохранить контрольную матрицу под новым именем, повторно открыть и получить 5. Попробовать открыть файл с недостающей строкой и отменить выбор файла. После обоих действий прежняя матрица должна давать 5.

### 5. Строка и вектор

По Enter или кнопке проверить, упорядочены ли строчные русские буквы по алфавиту. Если порядок нарушен, вывести отсортированную строку. Учитывать положение ё между е и ж. Для вектора сгенерировать целые числа из диапазона [−106; 106] и вывести новый массив из сумм соседних элементов: B[i] = A[i] + A[i+1].

**Проверка:** «жёе» → «еёж», «еёёж» уже упорядочена. Для [3, −1, 4, 0] получить [2, 3, 4]. Сверить существующие обработчики до правок.

### 6. Полярная кривая «Клевер»

По кнопке «Нарисовать» очищать Chart. Каждые 100 мс добавлять точку для r = 2 + cos(3φ) sin(2φ), x = r cos φ, y = r sin φ. Завершить при φ = 2π и остановить таймер. Использовать одинаковый масштаб единицы по обеим осям.

**Проверка:** при φ = 0 и 2π точка (2, 0), при φ = π точка (−2, 0), при φ = π/4 радиус равен 2 − √2/2. Повторный старт очищает график.

### 7. Случайное блуждание

Отобразить 78 ячеек с координатами 0…77. Начальная позиция 38. Один шаг каждые 100 мс, влево и вправо с равными вероятностями. Отражать шаг наружу на границах. «Стоп» сохраняет позицию, «Старт» продолжает с неё.

**Проверка:** из 0 следующий шаг ведёт в 1, из 77 — в 76. Частица не движется во время паузы и продолжает после нажатия «Старт».

### 8. Испытания в Windows

Собрать и запустить рабочую копию в Visual Studio под Windows. Подготовить таблицу «Действие | Ожидаемый результат | Фактический результат» по проверкам этапов 2–7. Включить неверный ввод, ошибку файла и повторные операции. Реальные скриншоты всех пяти разделов сохранить в cursach/screenshots. Если чат работает в macOS, передать пользователю пошаговую инструкцию и получить фактические результаты.

**Проверка:** зафиксированы результат сборки и каждого испытания, сохранены скриншоты. После исправлений повторены соответствующие испытания.

### 9. Бланк и пояснительная записка

Подготовить отдельные итоговые копии документов по исходным шаблонам. Уточнить недостающие персональные данные и даты. Описать введение, состав проекта, классы, элементы и изменённые свойства, ограничения, руководства программиста и пользователя, заключение и литературу. В приложение А включить обработчики с комментариями, в приложение Б — испытания, скриншоты и ручной подсчёт пяти подходящих элементов.

**Проверка:** тема совпадает со списком вариантов, описание соответствует итоговому коду, результаты подтверждены этапом 8. Визуально проверить оглавление, подписи и страницы. До сдачи подтвердить допустимость C#.
